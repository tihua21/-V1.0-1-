## 二、现有系统走查汇报

**【汇报人：查元昊】**

本周共完成两个系统的走查：电子科技大学预约系统（普通用户端，实际操作）和智会云——智能会议室管理系统（管理员端，基于教师提供的演示截图分析）。

### （一）普通用户端走查要点

**任务1：查询并预约会议室**

- 操作过程：登录 → 进入会议室列表 → 查看会议室状态 → 选择日期和时间 → 填写预约信息 → 提交预约 → 查看预约结果。
- 系统反馈：预约成功弹出气泡提示；生成预约凭证，显示会议室名称、预约时段、预约人信息、预约备注，状态标注为“已预约”。
- 发现规则：会议室列表支持按分类筛选；状态按时段以表格形式呈现；鼠标悬停可查看时段详情；每个预约时段固定为30分钟；同一会议室同一时段仅允许一人预约；预约成功后自动生成凭证和操作记录。
- 发现问题：预约时段固定30分钟，无法灵活选择时长，如需45分钟只能选2个时段，产生15分钟冗余；预约凭证缺少唯一预约编号，不便查询追溯。

**任务2：查看、修改或取消预约**

- 操作过程：进入“我的消息”查看操作记录 → 查看预约详情 → 点击“取消预约” → 确认二次提示框 → 查看取消后状态变化 → 查看并修改操作记录 → 查看用户中心。
- 系统反馈：取消预约有二次确认弹窗，取消成功弹出气泡提示；删除操作记录有二次确认，删除成功弹出气泡提示。
- 发现规则：操作记录统一存放在“我的消息”；取消前需二次确认；取消后时段重新开放；取消操作生成记录；可删除记录；用户中心支持个人信息管理。
- 发现问题：系统不提供预约修改功能，用户只能取消后重新预约，存在时段被抢占风险；取消规则未明确；删除操作记录后是否可追溯不明确。

### （二）管理员端走查要点

**任务3：管理员——维护会议室或处理预约**

- 操作过程：登录进入后台首页 → 查看运营概览和待审核事项 → 用户管理（搜索/添加/编辑）→ 会议室管理（搜索/添加/编辑）→ 预订管理（查看/审核）→ 用户反馈处理。
- 系统反馈：首页实时显示运营数据；用户/会议室增删改后列表更新；预约支持审核通过/驳回；反馈支持状态变更；操作成功有气泡提示。
- 发现规则：添加用户时登录账号必填且唯一；编辑用户可修改状态；添加/编辑会议室需填写名称、位置、容量、设备、状态；预约状态包含“待审核”“已预约”“已取消”；反馈支持状态进度更新。
- 发现问题：编辑用户和会议室没有提示/验证，可能导致误操作；编辑会议室“初始状态”含义不明；预约管理界面“通过”“驳回”容易误操作，且与“编辑/取消”并列，功能分区不清晰；缺少审核日志。

## 三、真实业务场景研讨

**【汇报人：查元昊】**

经过走查记录和小组讨论，最终冻结以下3个标准真实业务场景：

### 场景1：普通用户成功预约会议室

- **来源**：电子科技大学预约系统走查记录、截图
- **使用角色**：普通用户
- **发生情景**：用户需要预约周二09:00-09:30的会议室
- **用户目标**：找到空闲会议室并成功提交预约申请
- **前置条件**：用户已登录系统；系统中存在可用的会议室
- **操作过程**：访问首页进入会议室列表 → 查看状态选择空闲时段 → 鼠标悬停查看详情 → 选择日期和时间 → 填写预约人信息 → 填写预约备注 → 提交预约
- **系统反馈**：预约成功弹出气泡提示；生成预约凭证，显示详情，状态标注为“已预约”
- **障碍或痛点**：预约时段固定30分钟，45分钟会议需选2个时段产生冗余；预约凭证无编号，不便追溯
- **期望改进**：支持自定义预约时长；生成唯一预约编号

### 场景2：普通用户修改预约

- **来源**：电子科技大学预约系统走查记录、截图
- **使用角色**：普通用户
- **发生情景**：用户已成功预约周二09:00-09:30的会议室，但因会议时间调整，需要改到周四下午同一时段
- **用户目标**：成功将预约修改为新的时间
- **前置条件**：用户已登录系统；用户已有有效的预约记录
- **操作过程**：进入“我的消息”查看记录 → 查看详情 → 点击“取消预约” → 确认二次提示框 → 取消成功释放时段 → 重新查看会议室状态选择空闲时段 → 选择日期和时间 → 填写预约人信息 → 填写备注 → 提交预约
- **系统反馈**：取消有二次确认弹窗；取消成功弹出气泡提示；取消后凭证状态变更，时段重新开放
- **障碍或痛点**：系统不提供直接修改功能，需取消后重新预约，存在时段被抢占风险；操作路径长
- **期望改进**：提供预约修改功能，保留原预约直至修改成功

### 场景3：管理员审核预约申请

- **来源**：智会云会议室预约系统走查记录、截图
- **使用角色**：管理员
- **发生情景**：用户提交预约申请后，需要管理员审核确认，管理员登录后台查看待审核事项并处理
- **用户目标**：管理员高效处理待审核预约申请，通过或驳回
- **前置条件**：管理员已登录后台；存在待审核的预约申请
- **操作过程**：管理员登录进入后台首页 → 查看“待审核事项” → 进入预订管理 → 筛选或查找待审核记录 → 查看预约详情 → 点击“通过”或“驳回” → 确认操作
- **系统反馈**：待审核列表出现待处理记录；审核通过后状态变更为“已预约”；操作成功有气泡提示
- **障碍或痛点**：操作按钮直接暴露在主界面，可能误操作；缺少二次确认，误判后无法撤回；缺少审核日志，无法追溯；按钮与“编辑/取消”并列，功能分区不清晰
- **期望改进**：增加独立操作区；增加二次确认；记录审核日志；按功能分组布局
