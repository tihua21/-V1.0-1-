## 一、决策结论

**本组选择 方案B（固定时段预约 + 管理员审核）方案作为"智能会议室管理系统 V1.0——基础预约与管理平台"的实施方案。**

选择理由是：方案B在用户操作难度、实现难度、开发工作量、数据库设计难度、时间冲突处理难度以及与本组能力匹配程度六个维度均优于方案A，综合评分 56/65 高于方案A的 50/65。固定时段离散化使核心冲突检测算法大幅简化为"时段是否被占用"的枚举判断，审核状态机逻辑清晰，开发风险可控；同时功能完整覆盖任务书规定的最低运行闭环，且与本组当前技术能力匹配度最高。

该方案能够完成用户登录、会议室查询、预约申请、时间冲突检测、我的预约管理以及管理员基础管理。

## 二、决策问题逐条回答

### 问题1：最终选择哪个方案？

**回答：选择方案B——固定时段预约 + 管理员审核。**

该方案以系统预置时段为基础，用户从预置时段中选择并提交预约申请，管理员审核通过后预约生效并生成唯一预约编号。方案在保证最低运行闭环的前提下，将核心算法离散化，降低实现难度。

### 问题2：选择该方案的主要原因是什么？

**回答：**

1. **实现难度可控**：时段为离散枚举，冲突检测简化为"时段ID是否被占用"的判断，无需处理区间重叠边界情况（如方案A的首尾相接、跨天判定）；
2. **开发工作量更小**：无需实现区间算法和事务一致性控制，主要工作集中在审核界面与日志记录；
3. **数据库设计更简单**：预约表按时段ID关联，结构清晰，无需考虑区间索引优化；
4. **用户操作直观**：用户只需从预置时段中点选，无需自行输入起止时间，降低使用门槛；
5. **与本组能力匹配**：审核状态机与界面开发为主，技术门槛较低，无需额外学习区间算法与事务控制；
6. **管理员闭环完整**：管理员可管理用户、会议室、时间段、审核预约并记录审核日志，满足任务书对管理员基础管理的要求。

### 问题3：该方案如何满足任务书规定的最低运行闭环？

**回答：**

方案B覆盖任务书规定的全部最低闭环功能：

| 闭环功能 | 方案B实现方式 |
|---|---|
| 用户登录和角色区分 | 普通用户与管理员双角色登录，权限区分 |
| 会议室信息管理 | 管理员可增删改查会议室（名称、位置、容量、设备、状态） |
| 会议室查询 | 用户可按位置、容量、设备筛选会议室，查看可预约时段 |
| 预约申请 | 用户选择未占用时段，填写信息后提交预约申请 |
| 时间冲突检测 | 同一会议室同一时段仅允许一人成功预约，直接判断占用 |
| 我的预约查看、修改和取消 | "我的预约"模块支持查看、改期申请、取消，取消后时段重新开放 |
| 管理员管理用户 | 管理员可增删改查用户，状态启用/停用 |
| 管理员管理会议室 | 管理员可管理会议室信息与预置时段 |
| 管理员查看和处理预约 | 管理员可查看待审核与全部预约，独立审核区"通过/驳回"，记录日志 |

### 问题4：放弃另一个方案的主要原因是什么？

**回答：放弃方案A（自由时间段预约）的主要原因：**

1. **区间冲突检测算法复杂**：需处理首尾相接、跨天、自定义粒度等边界情况，算法实现难度较高；
2. **修改事务一致性风险**：修改预约时需"保留原预约至新预约成功"的事务控制，并发场景下易出现原预约被误释放；
3. **开发工作量偏大**：需额外实现区间算法、时间输入日历组件、自定义粒度处理，工作量超出本组当前能力；
4. **数据库区间查询性能风险**：自定义粒度过细时，区间查询性能下降，需额外优化；
5. **与本组能力匹配度较低**：需额外学习区间算法与事务控制，学习成本较高。

方案A的主要优势在后续扩展能力（为重复预约、智能推荐提供基础），但该优势在V1.0阶段非必需，可在后续版本中通过改造数据结构实现。

### 问题5：当前方案最大的风险是什么？

**回答：方案B当前最大的风险是审核延迟导致用户体验下降。**

具体表现：
1. 预约提交后为"待审核"状态，需管理员审核通过后才生效，用户在等待期间无法确认预约结果；
2. 若管理员处理不及时，可能导致用户重复提交或转向其他会议室，增加管理负担；
3. 时段预置若不合理（如缺少45分钟时段），仍可能造成资源浪费，削弱方案B相对方案A的优势；
4. 审核日志与预约状态需保证一致性，日志记录失败可能导致追溯困难。

### 问题6：准备采用什么办法降低风险？

**回答：**

| 风险 | 降低措施 |
|---|---|
| 审核延迟影响体验 | 1. 预约提交后即时反馈"待审核"状态与预计处理时限；2. 管理员端待审核列表置顶提醒；3. 预留"自动通过"规则：距开始时间不足X小时且无冲突的预约自动通过 |
| 时段预置不合理 | 1. 初始预置覆盖 30/45/60 分钟三档时段；2. 管理员可动态增删时段；3. 上线后根据预约数据统计分析并优化时段配置 |
| 审核日志与状态一致性 | 1. 审核操作与日志记录在同一数据库事务中完成；2. 定期校验日志与预约状态一致性；3. 异常时以日志为准回写状态 |
| 管理员审核误操作 | 1. 独立审核操作区，与查看区分开；2. 通过/驳回前二次确认；3. 日志记录操作人、时间、类型、前后状态，便于追溯 |
| 用户重复提交 | 1. 同一时段仅允许一次有效申请；2. 提交后按钮置灰并显示状态；3. "我的预约"中实时展示当前申请状态 |
