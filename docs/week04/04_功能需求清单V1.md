## 一、功能需求清单

| 编号 | 需求描述（谁用、做什么、系统怎样反馈） | 优先级 | 来源 | 对应第2周问题 |
|------|----------------------------------------|--------|------|----------------|
| FR-01 | 普通用户和管理员登录时，系统校验账号密码；校验通过后根据角色跳转到不同主页，显示对应菜单。普通用户看不到管理入口，管理员看不到普通用户的预约提交入口。越权请求返回403。 | 必须 | V1.0范围第1条 | P02 越权访问 |
| FR-02 | 管理员可新增、编辑、查询、停用/启用会议室，维护名称、位置、容量、设备、状态。新增时若编号重复，系统提示“该编号已存在”；停用后该会议室不可被预约。 | 必须 | V1.0范围第2条 | P03 检索盲目 |
| FR-03 | 普通用户可按位置、容量、设备等条件筛选会议室，系统返回符合条件的会议室列表；无结果时提示“未找到符合条件的会议室”。用户可查看某会议室某天的预置时段及占用状态。 | 必须 | V1.0范围第3条 | P03 检索盲目 |
| FR-04 | 普通用户选择会议室、日期和未被占用的预置时段，填写用途后提交预约申请；系统执行冲突检测，无冲突则生成状态为“待审核”的预约记录，并提示“预约申请已提交，请等待管理员审核”；有冲突则拒绝并提示已占用时段。 | 必须 | V1.0范围第4条 | P01 时段固定30分钟 |
| FR-05 | 提交预约时，系统按半开区间 [start, end) 判断冲突：同一会议室同一时段仅允许一条有效预约（状态为“待审核”或“已预约”）；当 start_new < end_old 且 end_new > start_old 时判冲突；相邻时段（end_new == start_old 或 start_new == end_old）不冲突。 | 必须 | V1.0范围第5条 | P01 时段固定30分钟 |
| FR-06 | 普通用户可在“我的预约”查看自己的预约记录及状态；对未开始的预约可申请改期或取消。改期时原预约保留至新预约审核通过；取消需二次确认，取消后时段释放。 | 必须 | V1.0范围第6条 | P03/P04 无修改功能、路径长 |
| FR-07 | 管理员可新增、编辑、查询、停用/启用用户，可重置密码（不可查看明文密码）。登录账号唯一；停用用户不能继续登录和提交预约。 | 必须 | V1.0范围第7条 | P02 越权访问 |
| FR-08 | 管理员可新增、编辑、删除预置时间段（如30/45/60分钟），作为会议室可预约时段的规则。该功能属于“管理员管理会议室”的细化。时段重叠或起止时间不合法时提示“时段设置不合法”。 | 必须 | V1.0范围第8条（细化） | P01 时段固定30分钟 |
| FR-09 | 管理员可查看全部预约记录，按用户、会议室、日期筛选；对待审核预约执行“通过”或“驳回”，操作前二次确认；通过后状态变为“已预约”并生成唯一预约编号，驳回则提示原因；对异常预约可驳回处理并填写原因。系统自动记录审核日志（操作人、时间、操作类型、操作前后状态）。 | 必须 | V1.0范围第9条 | P05/P06/P07 审核误操作、无日志、功能分区不清 |
| FR-10 | 开发人员设计数据库，系统初始化时自动建表。数据库包含用户、角色、会议室、时间段、预约、审核日志等核心实体，主键、外键、状态和时间约束完整。 | 必须 | V1.0范围第10条 | — |
| FR-11 | 测试人员执行测试，系统需提供至少10条功能/异常测试用例，覆盖正常预约、冲突、权限、停用等场景，并记录测试结果和修复情况。 | 必须 | V1.0范围第11条 | P05 审核误操作 |
| FR-12 | 演示者按README启动系统，系统能完成环境安装、数据库初始化、前后端启动，并现场演示核心闭环（登录→查询→预约→冲突检测→审核→我的预约）。 | 必须 | V1.0范围第12条 | P01 时段固定30分钟 |
