## 二、用例详细描述

### UC-01 登录

| 项目 | 内容 |
|------|------|
| 用例名称 | 登录 |
| 参与者 | 普通用户、管理员 |
| 前置条件 | 用户已打开系统登录页 |
| 主流程 | 1. 用户输入账号和密码；2. 系统校验账号密码；3. 校验通过后，根据角色跳转到对应主页（普通用户前台 / 管理员后台） |
| 异常流程 | 账号或密码错误 → 提示“账号或密码错误”，返回登录页；账号被停用 → 提示“账号已停用，请联系管理员” |
| 后置条件 | 用户进入系统，获得对应角色的功能菜单 |
| 关联需求 | FR-01 用户登录和角色区分 |


### UC-02 查询会议室

| 项目 | 内容 |
|------|------|
| 用例名称 | 查询会议室 |
| 参与者 | 普通用户 |
| 前置条件 | 用户已登录 |
| 主流程 | 1. 用户进入会议室查询页；2. 输入或选择筛选条件（位置、容量、设备等）；3. 系统返回符合条件的会议室列表；4. 用户点击某会议室，查看详情及可预约时段 |
| 异常流程 | 无匹配结果 → 提示“未找到符合条件的会议室” |
| 后置条件 | 用户获取会议室信息，可进入提交预约流程 |
| 关联需求 | FR-03 会议室查询 |


### UC-03 提交预约

| 项目 | 内容 |
|------|------|
| 用例名称 | 提交预约 |
| 参与者 | 普通用户 |
| 前置条件 | 用户已登录；已选定会议室和预置时段 |
| 主流程 | 1. 用户选择会议室、日期和未被占用的预置时段；2. 填写预约用途等信息；3. 点击提交；4. 系统执行 UC-04 冲突检测；5. 检测通过后，生成预约申请，状态为“待审核”；6. 提示“预约申请已提交，请等待管理员审核” |
| 异常流程 | 时段已被占用 → 提示“该时段已被占用，请重新选择”；会议室已停用 → 提示“该会议室已停用，无法预约” |
| 后置条件 | 新增一条预约记录，状态为“待审核”，可在“我的预约”中查看 |
| 关联需求 | FR-04 预约申请；FR-05 冲突检测 |


### UC-04 冲突检测

| 项目 | 内容 |
|------|------|
| 用例名称 | 冲突检测 |
| 参与者 | 系统（被 UC-03 包含） |
| 前置条件 | 用户提交预约申请 |
| 主流程 | 1. 系统获取目标会议室、目标时段的已有有效预约（状态为“待审核”或“已预约”）；2. 判断目标时段是否已被占用；3. 若未被占用，返回“无冲突”；若已被占用，返回“冲突” |
| 异常流程 | 无 |
| 后置条件 | 返回冲突检测结果，供 UC-03 决定是否提交成功 |
| 关联需求 | FR-05 冲突检测（半开区间 [start, end)，相邻不冲突） |


### UC-05 管理我的预约

| 项目 | 内容 |
|------|------|
| 用例名称 | 管理我的预约 |
| 参与者 | 普通用户 |
| 前置条件 | 用户已登录 |
| 主流程 | 1. 用户进入“我的预约”；2. 系统展示当前用户的所有预约记录及状态；3. 用户可查看详情；4. 对于未开始的预约，可选择“申请改期”（UC-06）或“取消预约”（UC-07） |
| 异常流程 | 预约已开始或已完成 → 不允许改期或取消，提示“该预约已开始，无法操作” |
| 后置条件 | 用户完成查看、改期或取消操作，预约状态更新 |
| 关联需求 | FR-06 我的预约查看、修改和取消 |


### UC-06 申请改期

| 项目 | 内容 |
|------|------|
| 用例名称 | 申请改期 |
| 参与者 | 普通用户 |
| 前置条件 | 用户已登录；存在未开始的预约记录 |
| 主流程 | 1. 用户选择要改期的预约；2. 选择新的会议室和预置时段；3. 提交改期申请；4. 系统检测新时段是否冲突；5. 无冲突则生成改期申请，状态为“待审核”；6. 原预约保留至新预约审核通过 |
| 异常流程 | 新时段冲突 → 提示“该时段已被占用，请重新选择” |
| 后置条件 | 生成新的待审核预约，原预约仍有效；新预约审核通过后原预约自动取消 |
| 关联需求 | FR-06 我的预约修改（改期） |


### UC-07 取消预约

| 项目 | 内容 |
|------|------|
| 用例名称 | 取消预约 |
| 参与者 | 普通用户 |
| 前置条件 | 用户已登录；存在未开始的预约记录 |
| 主流程 | 1. 用户选择要取消的预约；2. 系统弹出二次确认框；3. 用户确认取消；4. 系统将预约状态更新为“已取消”，释放对应时段；5. 提示“取消成功” |
| 异常流程 | 用户取消二次确认 → 操作终止；预约已开始 → 提示“该预约已开始，无法取消” |
| 后置条件 | 预约状态变为“已取消”，该时段可被其他用户预约 |
| 关联需求 | FR-06 我的预约取消 |


### UC-08 管理用户

| 项目 | 内容 |
|------|------|
| 用例名称 | 管理用户 |
| 参与者 | 管理员 |
| 前置条件 | 管理员已登录 |
| 主流程 | 1. 管理员进入用户管理；2. 可查看用户列表、搜索用户；3. 可新增用户（填写登录账号、用户名、初始密码、性别、邮箱、手机号等）；4. 可编辑用户信息、重置密码、修改状态（正常/停用）；5. 可删除用户 |
| 异常流程 | 登录账号重复 → 提示“该登录账号已存在”；必填项为空 → 提示补充完整 |
| 后置条件 | 用户信息更新，系统记录操作 |
| 关联需求 | FR-07 管理员管理用户 |


### UC-09 管理会议室

| 项目 | 内容 |
|------|------|
| 用例名称 | 管理会议室 |
| 参与者 | 管理员 |
| 前置条件 | 管理员已登录 |
| 主流程 | 1. 管理员进入会议室管理；2. 可查看会议室列表、搜索会议室；3. 可新增会议室（填写名称/编号、位置、容量、设备设施、状态）；4. 可编辑会议室信息；5. 可停用/启用会议室；6. 可删除会议室 |
| 异常流程 | 会议室编号重复 → 提示“该编号已存在”；必填项为空 → 提示补充完整 |
| 后置条件 | 会议室信息更新，停用的会议室不可被预约 |
| 关联需求 | FR-02 管理员管理会议室 |


### UC-10 管理时间段

| 项目 | 内容 |
|------|------|
| 用例名称 | 管理时间段 |
| 参与者 | 管理员 |
| 前置条件 | 管理员已登录 |
| 主流程 | 1. 管理员进入时间段管理；2. 可查看已预置的时段列表；3. 可新增时段（如 08:00–08:30、08:30–09:00、09:00–09:45 等）；4. 可编辑或删除时段 |
| 异常流程 | 时段重叠或起止时间不合法 → 提示“时段设置不合法” |
| 后置条件 | 预置时段更新，普通用户可预约新的时段 |
| 关联需求 | FR-08 管理员管理时间段 |


### UC-11 查看和处理预约

| 项目 | 内容 |
|------|------|
| 用例名称 | 查看和处理预约 |
| 参与者 | 管理员 |
| 前置条件 | 管理员已登录 |
| 主流程 | 1. 管理员进入预约管理；2. 可查看全部预约记录，按用户、会议室、日期筛选；3. 对待审核预约，执行 UC-12 审核预约；4. 对异常预约，执行 UC-13 强制取消预约 |
| 异常流程 | 无 |
| 后置条件 | 预约状态更新，操作日志记录 |
| 关联需求 | FR-09 管理员查看和处理预约 |


### UC-12 审核预约

| 项目 | 内容 |
|------|------|
| 用例名称 | 审核预约 |
| 参与者 | 管理员 |
| 前置条件 | 存在待审核的预约申请 |
| 主流程 | 1. 管理员在待审核列表中选择一条预约；2. 查看预约详情；3. 点击“通过”或“驳回”；4. 系统弹出二次确认框；5. 确认后，系统更新预约状态（通过→已预约；驳回→已驳回）；6. 执行 UC-14 记录审核日志；7. 若通过，生成唯一预约编号 |
| 异常流程 | 管理员取消二次确认 → 操作终止 |
| 后置条件 | 预约状态更新，审核日志记录完整 |
| 关联需求 | FR-09 管理员处理预约；FR-05 冲突检测（审核时再次校验） |


### UC-13 强制取消预约

| 项目 | 内容 |
|------|------|
| 用例名称 | 强制取消预约 |
| 参与者 | 管理员 |
| 前置条件 | 存在异常预约或需强制取消的预约 |
| 主流程 | 1. 管理员在预约列表中选择目标预约；2. 点击“强制取消”；3. 填写取消原因；4. 系统弹出二次确认框；5. 确认后，预约状态变为“已取消”，释放时段；6. 执行 UC-14 记录审核日志 |
| 异常流程 | 管理员取消二次确认 → 操作终止 |
| 后置条件 | 预约状态更新，审核日志记录完整 |
| 关联需求 | FR-09 管理员处理预约 |


### UC-14 记录审核日志

| 项目 | 内容 |
|------|------|
| 用例名称 | 记录审核日志 |
| 参与者 | 系统（被 UC-12、UC-13 包含） |
| 前置条件 | 管理员完成审核或强制取消操作 |
| 主流程 | 1. 系统获取操作人、操作时间、操作类型、预约编号、操作前后状态；2. 写入审核日志表；3. 返回记录成功 |
| 异常流程 | 日志写入失败 → 回滚操作，提示“系统错误，请重试” |
| 后置条件 | 审核日志新增一条记录，可追溯 |
| 关联需求 | FR-09 记录审核日志 |
